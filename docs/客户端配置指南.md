# 客户端配置指南

本文档给出**直接可填的值**。所有 URL、API Key、模型 ID 都经过实测验证。

## 直接粘这些值

按客户端**照抄**下面对应的那一行，不要自己加减 `/v1`：

| 客户端 | 填的字段 | 粘贴这个值 |
|---|---|---|
| **Claude Code** | `ANTHROPIC_BASE_URL` | `http://127.0.0.1:4000` |
| **Codex** | `base_url` | `http://127.0.0.1:4000/v1` |
| **OpenCode / OpenAI SDK** | `baseURL` | `http://127.0.0.1:4000/v1` |
| **CC Switch** | Base URL | `http://127.0.0.1:4000` |
| 所有客户端 | API Key | `dummy` |

> **为什么 Claude Code 不带 `/v1`，Codex 却带？**
> LiteLLM 把 Anthropic 的 `/v1/messages` 挂在**根路径**下，Claude Code 会自己补 `/v1`——
> 你若填了 `/v1` 就变成 `/v1/v1/messages`，直接 `404`（实测）。
> Codex 和 OpenAI SDK 则要求你自己带上 `/v1`，它们只补 `/responses` 或 `/chat/completions`。
> **一句话：上表照抄，别改。**

> **API Key 填 `dummy` 即可。** 真正的 UJN API Key 已经在 `litellm_config.yaml` 里注入好了，
> 由代理转发。填任何值都行，但不能留空（部分客户端会拒绝空值）。

> **`127.0.0.1` 必须走直连。** 如果你开着系统代理或梯子，把
> `localhost,127.0.0.1` 加入 `NO_PROXY` / `no_proxy`。

### 可用端点（排查用）

```
GET  http://127.0.0.1:4000/health/liveliness     健康检查
GET  http://127.0.0.1:4000/v1/models             模型列表
POST http://127.0.0.1:4000/v1/chat/completions   OpenAI 协议
POST http://127.0.0.1:4000/v1/messages           Anthropic 协议（Claude Code）
POST http://127.0.0.1:4000/v1/responses          Responses 协议（Codex）
```

## 启动代理（配置客户端之前先做这步）

```powershell
cd D:\git_software\UJN_LLM_API
.\run.ps1
```

或者分步手动：

```powershell
uv run python ujn_webvpn_login.py --headless   # 登录 WebVPN，拿到 Cookie
uv run python build_litellm_config.py          # 生成 litellm_config.yaml
uv run litellm --config litellm_config.yaml --port 4000 --host 127.0.0.1
```

验证是否可用：

```powershell
Invoke-RestMethod http://127.0.0.1:4000/health/liveliness     # -> "I'm alive!"
Invoke-RestMethod http://127.0.0.1:4000/v1/models             # -> 8 个模型 id
```

## 可选模型 ID（实测于 2026-09-14，共 8 个）

模型**直接以原名对外暴露**，不做别名映射 —— 客户端填的就是下表的名字。
下表 8 个**都能调用**，只是推荐程度不同；`不推荐` ≠ `不可用`。

> ⚠ **上游会更新**（模型下线、新增、改名），本表是 **2026-09-14** 的快照，不是永久保证。
> 以 `--list-upstream` 的实时输出为准，见下文「怎么查看当前可用的模型」。

| 模型 ID | 上下文 | Claude Code | 说明 |
|---|---|---|---|
| `deepseek-v41-flash` | **1M** | ✅ | ⭐ 推荐：最新 + 上下文最大 |
| `GLM-5.3-Flash` | **1M** | ✅ | ⭐ 推荐：最快（实测 1.6s） |
| `deepseek-v4-flash` | **1M** | ✅ | 可用，上下文大 |
| `GLM-5.3` | 128K | ✅ | 可用但**不推荐**：唯一不是 1M；最慢（5.0s） |
| `Qwen3.8-27B` | 256K | ❌ | 可用，但 **Claude Code 用不了**（见下） |
| `Qwen3.6-27B` | 256K | ❌ | 同上 |
| `/models/Qwen3.8-Flash-Next` | 256K | ❌ | 同上 |
| `1.Qwen3.5-27B` | — | ❌ | 可用但**最不推荐**：最旧（3.5 世代） |

**推荐搭配：** 四个档位全部用 `deepseek-v41-flash` 与 `GLM-5.3-Flash` 两个 1M 模型轮换。

**注意 `/models/Qwen3.8-Flash-Next` 带斜杠**，这是上游真实的模型 id，照抄即可。

### 怎么查看当前可用的模型

上游模型会变（下线、新增）。**遇到 `Model not found` 就是上游清单变了**，按下面两步查。

**1) 查本代理对外暴露了哪些**（这些就是客户端能填的名字）：

```powershell
(Invoke-RestMethod http://127.0.0.1:4000/v1/models).data.id
```

也可以看详细信息：

```powershell
$models = Invoke-RestMethod http://127.0.0.1:4000/v1/models
$models.data | Format-List id, owned_by
```

**用返回列表里的 id 作为模型名。**

**2) 查上游实际有哪些**（比上一步更权威，且带上下文长度）：

```powershell
uv run python build_litellm_config.py --list-upstream
```

输出形如：

```
GLM-5.3  (ctx=131072)
GLM-5.3-Flash  (ctx=1048576)
deepseek-v41-flash  (ctx=1048576)
...
```

把上游新出现的名字加进 `models.yaml`，重新生成配置并重启：

```powershell
uv run python build_litellm_config.py
# Ctrl+C 停掉代理，再重跑 run.ps1
```

删模型同理（从 `models.yaml` 去掉后重新生成并重启）。

### ⚠ Qwen 系列不能用在 Claude Code 里

实测：Qwen 系（`Qwen3.8-27B`、`Qwen3.6-27B`、`/models/Qwen3.8-Flash-Next`、`1.Qwen3.5-27B`）
**在 Claude Code 里必然 400**，与配置无关：

```
400: System message must be at the beginning.
```

原因：Claude Code 会把 `Available agent types...` 那段以 **`role: "system"` 消息**的形式塞进
`messages` 数组的**第 2 条**（不是开头的 `system` 字段）。上游 vLLM 对 Qwen 系强制要求
system 消息必须在最前面，deepseek / GLM 系则宽容接受。这是 Claude Code 的行为，
代理层无法修正。**OpenAI 兼容客户端（OpenCode、SDK）用 Qwen 正常** —— 只有 Claude Code 受限。

### ⚠ `[1M]` 后缀：Claude Code 要加，其他客户端不要加

这两个结论不矛盾，因为后端不同：

| 场景 | 写法 |
|---|---|
| **Claude Code** 的 `ANTHROPIC_MODEL` / 各档位 | **要加** `[1M]`：`deepseek-v41-flash[1M]` |
| 其他客户端（curl、OpenCode、SDK、Codex） | **不要加**：`deepseek-v41-flash` |

- `[1M]` / `[1m]` 是 **Claude Code 自己认得的特殊标记**，它在发请求前会把后缀剥掉，
  并用它来把上下文窗口记为 1M。**不加的话 Claude Code 只当 200k**，会提前 auto-compact。
  它自己也会提示：`append [1m] to the model name for 1M`。
- 但**只有 `[1m]` 这个标记会被剥**。写 `[BOGUS]`、`[999k]` 等会原样透传给 LiteLLM，
  查不到模型名直接 `400`。
- 其他客户端不做这种剥离，所以 `[1M]` 会原样传过去变成 `400`。**照抄表里的裸名即可。**

## Claude Code

Claude Code 说 Anthropic 协议，本代理**原生支持** `/v1/messages`，所以**不需要 CC Switch**
做协议转换，直接连即可。

### 方式一：改 `~/.claude/settings.json`（推荐，永久生效）

在 `env` 段里加上（或改成）：

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "dummy",
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:4000",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "deepseek-v41-flash[1M]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "deepseek-v41-flash[1M]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "GLM-5.3-Flash[1M]",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "GLM-5.3-Flash[1M]",
    "ANTHROPIC_MODEL": "deepseek-v41-flash[1M]",
    "NO_PROXY": "localhost,127.0.0.1",
    "no_proxy": "localhost,127.0.0.1"
  }
}
```

- `ANTHROPIC_BASE_URL` 照抄上面「直接粘这些值」表里 Claude Code 那行即可。
- **四个档位都要带 `[1M]`**（Claude Code 专用标记，会被它自己剥掉；不带只算 200k）。
- 四个档位在 `deepseek-v41-flash` / `GLM-5.3-Flash` 两个 1M 模型间轮换。
- ⚠ 不要用 Qwen 系或 `GLM-5.3`：Qwen 系在 Claude Code 里必然 400（见上文），
  `GLM-5.3` 只有 128K。
- 改完**重启 Claude Code** 生效。

### 方式二：只用临时配置（不改全局，适合试跑）

新建一个 `my-cc.json`，内容同上，然后：

```powershell
claude --settings my-cc.json
```

### 方式三：环境变量（临时，优先级低于 settings.json）

```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:4000"
$env:ANTHROPIC_AUTH_TOKEN = "dummy"
claude
```

> ⚠ **`settings.json` 里的 `env` 优先级高于 shell 环境变量。** 如果你已经按方式一配过，
> 光设环境变量是不会生效的——它会继续用 settings.json 里的地址。

### 验证

```powershell
claude -p "只回答数字：1+1"
```

### 已知注意事项

- **扩展思考（thinking）需要代理已正确配置。** 本项目用 `hosted_vllm` provider 前缀就是为了
  让带 `thinking` 的请求不被错误地路由到上游不存在的 `/responses` 端点。若你看到
  `400 ... {"detail":"'messages'"}`，说明 `litellm_config.yaml` 是旧版——重新跑一次
  `build_litellm_config.py` 并重启代理。
- Claude Code 可能提示 `[claude-code:unrecognized_model]`，这只是它不认识非 Claude 模型名，
  **不影响使用**。
- 报 502 或要求登录 → WebVPN Cookie 过期，重跑 `uv run python ujn_webvpn_login.py --headless`。

## Codex

Codex 说 **Responses 协议**（`POST /v1/responses`），本代理原生支持。

> ⚠ **当前版本的 Codex 只接受 `wire_api = "responses"`。** 旧的 `wire_api = "chat"`
> 已被官方移除，写了会直接报错：
> `` `wire_api = "chat"` is no longer supported. ``

### 配置 `~/.codex/config.toml`

合并以下内容：

```toml
model = "deepseek-v41-flash"
model_provider = "ujn"

[model_providers.ujn]
name = "UJN LLM API"
base_url = "http://127.0.0.1:4000/v1"
env_key = "UJN_DUMMY_KEY"
wire_api = "responses"
request_max_retries = 3
stream_max_retries = 3
stream_idle_timeout_ms = 300000
```

- `base_url` 照抄上面「直接粘这些值」表里的 Codex 那行即可。
- `model` 填模型表里任意 ID。推荐 `deepseek-v41-flash` 或 `GLM-5.3-Flash`（都是 1M）。
- **Codex 不是 Claude Code，模型名不要带 `[1M]`** —— 原样填 `deepseek-v41-flash` 即可。

### 设置环境变量

Codex 要求 `env_key` 指向的环境变量**存在**（值本身无意义）：

```powershell
setx UJN_DUMMY_KEY "dummy"
```

设完要**重开终端**才能读到。

### 验证

```powershell
codex exec "只回答数字：1+1" --skip-git-repo-check
```

## CC Switch（多供应商切换，可选）

CC Switch 是供应商切换器。**本项目不需要它做协议转换**（Claude Code 有方式一直连），
但如果你想在多个供应商之间切换，可以把它作为 Claude Code 的供应商管理工具。

参考 `clients/ccswitch.json`。核心字段：

| 字段 | 填什么 |
|---|---|
| Provider 名称 | 任意，如 `ujn-llm` |
| API Format | **`anthropic`**（不是 `openai_chat`——本代理原生说 Anthropic 协议） |
| Base URL | `http://127.0.0.1:4000` （**不带 `/v1`**） |
| API Key | `dummy` |
| Fable 模型 | `deepseek-v41-flash[1M]` |
| Opus 模型 | `deepseek-v41-flash[1M]` |
| Sonnet 模型 | `GLM-5.3-Flash[1M]` |
| Haiku 模型 | `GLM-5.3-Flash[1M]` |

> CC Switch 是给 Claude Code 用的，所以**档位模型名同样要带 `[1M]`**（理由见上文）。

> 旧项目用的是 `apiFormat: "openai_chat"` + `baseURL: .../v1`（因为当时靠 CC Switch 做
> OpenAI→Anthropic 转换）。**现在不要那么填**——本代理自己就说 Anthropic，让 CC Switch
> 再转一层反而会出错。

## OpenCode / 其他 OpenAI 兼容客户端

参考 `clients/opencode.json`。通用填法：

```
Base URL:  http://127.0.0.1:4000/v1
API Key:   dummy
Model:     上表里任意 ID（OpenCode 推荐用上游原名，如 GLM-5.3、deepseek-v41-flash）
```

Python 客户端示例：

```python
import httpx
from openai import OpenAI

client = OpenAI(
    api_key="dummy",
    base_url="http://127.0.0.1:4000/v1",
    http_client=httpx.Client(trust_env=False),   # 关键：绕开系统代理
)

resp = client.chat.completions.create(
    model="GLM-5.3",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

## 常见问题

**`400 ... {"detail":"'messages'"}`**
两个 bridge 开关缺了一个，或用了旧的 `openai/` provider 前缀。
解决：`uv run python build_litellm_config.py` 重新生成，然后重启代理。
（`litellm_config.yaml` 里应看到 `hosted_vllm/` 和两处 `use_chat_completions*`。）

**`400 Model not found`**
上游清单变了（模型下线或改名）。先查上游现在有什么：

```powershell
uv run python build_litellm_config.py --list-upstream
```

再查本代理对外暴露了什么（客户端能填的名字以这个为准）：

```powershell
(Invoke-RestMethod http://127.0.0.1:4000/v1/models).data.id
```

把新名字加进 `models.yaml`，重新生成配置并重启代理。详见上文「怎么查看当前可用的模型」。

**启动即崩溃，`UnicodeDecodeError: 'gbk'`**
`litellm_config.yaml` 里混进了非 ASCII 字符。LiteLLM 用系统默认编码读该文件（Windows 是 GBK）。
生成器已内置检查，重新生成即可。

**`502` / `302` / 要求登录**
WebVPN Cookie 过期。重跑：

```powershell
uv run python ujn_webvpn_login.py --headless
uv run python build_litellm_config.py
```

然后重启代理。

**Claude Code 连不上 / 还在走旧端口**
检查 `~/.claude/settings.json` 的 `env.ANTHROPIC_BASE_URL`——它的优先级高于环境变量。
旧项目指向 `8000`，本项目是 `4000`。

**间歇性 400**
上游（Open WebUI / vLLM）偶发的 400，实测约 3% 的请求。可在 `litellm_settings` 里
调大 `request_max_retries` 缓解。

**Qwen 系报 `400: System message must be at the beginning.`**
Claude Code 发来的请求里，`Available agent types...` 那段是以 `role: "system"` 消息形式
放在 `messages` 数组**第 2 条**的（不是开头的 `system` 字段）。上游 vLLM 对 Qwen 系强制要求
system 消息必须在最前面，deepseek / GLM 系则接受。**这是 Claude Code 的行为，代理层改不了。**
解法：Claude Code 里别用 Qwen 系，用 `deepseek-v41-flash` 或 `GLM-5.3-Flash`。
OpenAI 兼容客户端（OpenCode、SDK）用 Qwen 不受影响。

**关于 effort 档位（low / medium / high / xhigh / max / ultracode）**
Claude Code 的 effort 是通过 `output_config.effort` 字段发的，不是标准的 `reasoning_effort`。
实测这些档位**不影响** `deepseek-v41-flash` / `GLM-5.3-Flash`（各档位均 200）。
若某个模型对 effort 取值挑食（实测 Qwen 系只接受 `low` / `medium`；`deepseek-v41-flash`
不接受 `medium`），可在该部署的 `litellm_params` 里加：

```yaml
additional_drop_params: ["reasoning_effort", "output_config", "context_management"]
```

让 LiteLLM 直接丢弃这些字段（模型本身仍会按其默认方式推理）。

**改了模型映射不生效**
改 `models.yaml` 后必须重新生成配置**并重启代理**：

```powershell
uv run python build_litellm_config.py
# 然后 Ctrl+C 停掉代理，重新运行 run.ps1
```
